# CLAUDE.md — qudtlib-js-i18n

## What this project is

A standalone ESM-only npm package that patches `@qudtlib/allunits` unit and quantity kind instances at import time with multilingual labels. `@qudtlib/allunits` only ships English labels; this package adds ~14,000 non-English labels from three sources without requiring any changes to the upstream library.

Users replace:
```typescript
import { Units, Qudt } from "@qudtlib/allunits";
```
with:
```typescript
import { Units, Qudt } from "qudtlib-js-i18n";
```

Everything from `@qudtlib/allunits` is re-exported. Labels are applied as a side effect at import time via `unit.addLabel()` / `qk.addLabel()`.

---

## Architecture

```
scripts/generate-labels.ts   # Run once to regenerate src/labels.ts
src/labels.ts                # GENERATED — checked in, ~14k labels
src/fr-translations.ts       # STATIC — manually curated AI French QK translations
src/de-translations.ts       # STATIC — AI German QK translations, NOT yet reviewed
src/index.ts                 # Re-exports allunits + applies labels
```

`src/labels.ts` is committed to the repo so consumers don't need to run the generator. It is regenerated weekly by GitHub Actions (`.github/workflows/update-labels.yml`).

## Key technical facts

### IRI format
- qudtlib-js uses **`http://`** IRIs (not `https://`), e.g. `http://qudt.org/vocab/unit/M`
- The QUDT Turtle files also use `http://` — no conversion needed
- This tripped us up early: an `http→https` normalisation was added then removed

### qudtlib-js API
- `Qudt.unit(iri)` — looks up a Unit by full IRI (requires `@qudtlib/allunits` to be imported first to register units)
- `Qudt.quantityKind(iri)` — looks up a QuantityKind
- `Qudt.prefix(iri)` — looks up a Prefix
- `Qudt.allUnits()`, `Qudt.allQuantityKinds()`, `Qudt.allPrefixes()`
- `unit.addLabel(new LangString(text, languageTag))` — public, works on Unit and QuantityKind
- `unit.getLabelForLanguageTag(tag)` — available on Unit and QuantityKind, **not on Prefix**
- `LangString` and `Qudt` are imported from `@qudtlib/core`

### Prefix labels
Prefix labels are **intentionally excluded**. The QUDT ontology only has 3 non-English prefix labels (`Deka/de`, `Etto/it`, `Chilo/it`) and they are already built into qudtlib-js itself — adding them again would create duplicates. Also, `Prefix` has no `getLabelForLanguageTag` method.

### Data sources

| Vocabulary | URL | IRIs | Non-English labels |
|---|---|---|---|
| QUDT units | `https://qudt.org/vocab/unit` | 957 | 11,481 |
| QUDT quantity kinds | `https://qudt.org/vocab/quantitykind` | 125 | 1,713 |
| Wikidata (FR, DE) | `https://query.wikidata.org/sparql` | fr +852, de +945 | fr +852, de +945 |
| AI translation (FR QK only) | `src/fr-translations.ts` | +707 | +707 |
| AI translation (DE QK only, unreviewed) | `src/de-translations.ts` | +689 | +689 |

**Wikidata properties:**
- `P2968` = QUDT unit ID (local name, e.g. `"M"`)
- `P8393` = QUDT quantity kind ID (local name, e.g. `"Mass"`)

Wikidata labels are only added where the QUDT ontology has no label in that language — QUDT always takes precedence. Languages are listed in `WIKIDATA_LANGS` in `generate-labels.ts`. Wikidata rate-limits (429) and flakes (502), so the fetch retries with backoff.

### AI translations (`src/fr-translations.ts`)
Static file — not regenerated by `npm run generate`. Contains French labels for the ~707 QuantityKinds not covered by QUDT or Wikidata. Exported as:
- `FR_QK_CONFIDENT: Record<string, string>` — 679 straightforward translations
- `FR_QK_UNCERTAIN: Record<string, [string, string]>` — 28 domain-specific entries, all reviewed/corrected by the project author

Both are applied as a fallback in `src/index.ts` (only where no French label already exists). To update or add entries, edit `src/fr-translations.ts` directly.

### AI translations (`src/de-translations.ts`)
Static file — not regenerated by `npm run generate`. Contains German labels for the 689 QuantityKinds not covered by QUDT or Wikidata, giving German 100% QK coverage. Exported as a single `DE_QK_TRANSLATIONS: Record<string, string>` — unlike the French file, this has **not** been split into confident/uncertain or reviewed by the project author yet. Applied as a fallback in `src/index.ts` (only where no German label already exists). To update or add entries, edit `src/de-translations.ts` directly.

### IPv6 / Wikidata timeout
Wikidata's SPARQL endpoint times out on IPv6 in some environments. Fixed by calling `dns.setDefaultResultOrder("ipv4first")` at the top of `generate-labels.ts`.

## Scope decisions

- **Units** ✅ — full multilingual support
- **QuantityKinds** ✅ — full multilingual support (100% French and German coverage)
- **Prefixes** ❌ — excluded (see above)
- **French + German enrichment via Wikidata** ✅ — fills gaps not in QUDT
- **AI-translated French QK labels** ✅ — `src/fr-translations.ts`; applied as fallback only where QUDT and Wikidata have no French label; split into `FR_QK_CONFIDENT` (679) and `FR_QK_UNCERTAIN` (28, all reviewed by project author)
- **AI-translated German QK labels** ✅ — `src/de-translations.ts`; applied as fallback only where QUDT and Wikidata have no German label; single unsplit `DE_QK_TRANSLATIONS` (689 entries), **not yet reviewed** by the project author
- **Other languages via Wikidata** — add the tag to `WIKIDATA_LANGS`

## Build & workflow

```bash
npm run generate     # Fetch QUDT + Wikidata, write src/labels.ts
npm run build        # tsc → dist/ (ESM, target ESNext)
```

- ESM-only (`"type": "module"` in package.json)
- `tsconfig.json` — `target: ESNext`, `module: NodeNext`
- `tsconfig.scripts.json` — used by `tsx` to run the generate script
- No CJS build (deliberately dropped in favour of ESM-only)

---

## Extending to more languages

Add the language tag to `WIKIDATA_LANGS` in `scripts/generate-labels.ts` and run `npm run generate`.
